# 面试拷打后的产品优化方案

日期：2026-09-09  
目标：把“知乎总结工具”升级成更像真实知乎站内产品的学习增强能力。

## 1. 核心升级结论

产品不能只讲“AI 总结知乎内容”。更强的定位是：

知炼 EchoMind 帮知乎把“高质量内容消费”升级成“可验证的学习转化”。它不是把回答缩短，而是判断这个问题是否适合学习、筛选值得参考的回答、识别评论区反例、匹配用户背景、生成行动清单，并用 3 道自测题触发错题复习卡片。

这套叙事能回答 5 个最危险问题：

- 为什么是知乎专属：因为使用问题语境、作者标签、赞同数、评论反例和多回答结构。
- 为什么是行动清单：因为用户要从经验内容走向下一步行动。
- 为什么需要多 Agent：因为质量判断、反例识别、经验蒸馏、行动生成、测验反馈是不同任务。
- 如何证明学习有效：通过自测题和错题复习卡片建立最小闭环。
- 开放接口不完整怎么办：MVP 用 adapter + mock，真实上线时按字段可用性降级。

## 2. 新增业务机制

### 2.1 学习意图识别

自动触发不应该等于每个问题都强行生成行动清单。系统先判断当前问题是否有学习价值。

适合触发：

- 如何入门某个领域。
- 如何学习某项技能。
- 如何准备考试、求职、转行。
- 如何做项目、建立方法论。
- 有多个回答提供路径、经验、步骤或反例。

不适合强触发：

- 单点事实查询。
- 情绪吐槽。
- 争议娱乐问题。
- 回答数量太少或结构过短。

产品表现：

- 高适配：自动生成行动清单并弹轻提示。
- 中适配：生成“问题拆解”，用户可点开行动清单。
- 低适配：只显示“这个问题更适合快速阅读”，避免打扰。

### 2.2 适用人群匹配

知乎经验的风险是“别人的路径不一定适合我”。侧边栏应该允许用户选择轻量画像：

- 身份：大学生、职场新人、转行者、自我提升。
- 目标：入门、求职、考试、做项目。
- 时间：30 分钟、1 小时、2 小时。

每条行动展示“适合你”的理由：

```text
适合你：高
原因：答主是独立开发者，经验目标也是 7 天 Demo，且行动可在 2 小时内启动。
```

MVP 可以先默认画像为“大学生 / 做项目 / 每天 2 小时”，保留切换控件。

### 2.3 经验可信度

高赞只是一个信号，不能等于可信。回答质量评分拆成 5 个维度：

| 维度 | 说明 |
|---|---|
| 热度 | 赞同数、互动量 |
| 身份贴合度 | 作者标签和用户画像是否接近 |
| 结构完整度 | 是否有步骤、时间线、检查标准 |
| 边界意识 | 是否说明适用条件、风险和反例 |
| 评论挑战 | 评论区是否出现强反例或过时提醒 |

普通用户只看标签：

- 优先参考
- 谨慎参考
- 仅作补充

评委 trace 才展示具体评分和计算依据。

### 2.4 评论区反例雷达

评论区不是事实来源，而是边界雷达。

反例雷达输出：

- 哪些建议可能过时。
- 哪些建议只适合特定背景。
- 哪些评论指出了执行失败的条件。
- 哪些评论和高赞回答冲突。

普通用户文案：

```text
反例提醒：如果你每天少于 1 小时，这条“先做完整架构”的建议可能不适合你。
```

### 2.5 最小学习闭环

不做完整学习系统，但保留最小闭环：

```text
行动清单 -> 3 道自测 -> 错因判断 -> 补 1 张复习卡片
```

这个闭环能证明产品不是一次性总结，而是在帮助用户吸收。

## 3. 新 MVP 模块

MVP-01 Question Fit Detector

- 判断问题是否适合学习增强。
- 输出 fit_level：high / medium / low。
- 高适配时自动触发并弹轻提示。

MVP-02 Zhihu Signal Adapter

- 读取模拟知乎字段：问题、回答、作者标签、赞同数、评论摘要。
- 为后续开放接口接入保留 adapter 边界。

MVP-03 Answer Quality Ranker

- 对回答打“优先参考 / 谨慎参考 / 仅作补充”标签。
- 评分依据包括赞同数、作者标签、结构完整度、边界意识、评论挑战。

MVP-04 Experience To Action

- 把高质量回答和反例提醒转成行动清单。
- 每条行动包含适用人群、原因、完成标准、来源、置信度。

MVP-05 Quiz And Review Card

- 默认生成 3 道自测题。
- 用户答错后补 1 张复习卡片。
- 复习卡片针对错因：概念、条件或步骤。

MVP-06 Judge Trace

- 普通用户默认不看 Agent。
- 评委模式展示各 Agent 的输入摘要、输出摘要、source_ids 和风险判断。

## 4. 页面体验优化

新 demo 应该更像知乎站内能力：

- 左侧是模拟知乎问题页。
- 中间是回答流，包含作者标签、赞同数和评论摘要。
- 右侧是知炼侧边栏。
- 页面加载后右侧自动分析，出现轻提示。
- 侧边栏首屏展示行动清单。
- trace 收在“评委模式”折叠面板里。

首屏信息顺序：

1. 轻提示：已为你炼成今日行动清单。
2. 问题适配度：适合炼成学习行动。
3. 今日行动：动态 3 到 5 条。
4. 适合你：基于用户画像的匹配说明。
5. 自测题：3 题。
6. 错题复习卡片。
7. 评委 trace。

## 5. 答辩口径

如果评委说“这就是总结 + Quiz”，回答：

```text
普通总结只压缩文本。知炼先判断问题是否适合学习，再利用知乎特有结构做质量判断：作者标签、赞同数、多回答结构和评论反例。最后它把经验转成行动清单，并用自测错因补复习卡片，形成从内容消费到学习吸收的闭环。
```

如果评委问“为什么需要多 Agent”，回答：

```text
因为这里不是一个生成任务，而是一条知识生产流水线。QualityRanker 判断哪些回答值得信，CommentSynthesizer 抓评论反例，Distiller 提炼经验原子，ActionCoach 转成行动，Quiz 检查掌握，Review 负责证据和边界。拆开后，每一步都能被 trace 和评测。
```

如果评委问“没有真实知乎接口怎么办”，回答：

```text
MVP 用 adapter 模拟开放接口字段，核心能力不依赖具体来源。真实接入时只替换 adapter；如果评论或作者标签不可用，系统会降级为回答内容 + 赞同数，并在 trace 里标记证据不足。
```

## 6. 下一轮实现重点

优先实现能一眼改变产品气质的功能：

1. 模拟知乎问题页布局。
2. 问题适配度和自动触发轻提示。
3. 回答质量标签：优先参考 / 谨慎参考 / 仅作补充。
4. 评论区反例雷达。
5. 行动清单取代学习路径成为首屏。
6. 3 道自测 + 错题补卡。
7. Agent trace 收进评委模式。
